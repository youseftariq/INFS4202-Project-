# Test design

A spreadsheet `docs/test-cases.xlsx` may replace this file. At least 10 test cases for each of the three primary modules.

## Test case matrix

### Applications (APP): owner Qudama

**Conventions for this section:**
- **Levels:** *API* = black-box call to the Engine (`http://127.0.0.1:8081/api/v1`); *Unit* = Portal class tested alone with JUnit 5 and Mockito; *Integration* = Portal service + H2 database with the Engine stubbed; *System* = running Portal in a browser after `./start.sh --reset`.
- **Settings:** defaults unless a row says otherwise: active limits GOOD 5 and PROBATION 2, shortlist threshold 60, default minimum GPA 2.00, default minimum credits 45.
- **Dates** for System tests are relative to the day of the `--reset` start, because the seed data is placed around that day.
- **Engine API test data** uses `asOf` 2026-11-24 and, unless a row says otherwise, a valid CV (PDF, 100 bytes) and a valid transcript (PDF, 100 bytes, issued 2026-11-01).
- **Status:** *Pass* or *Fail* = executed, actual result recorded; *Not run* = designed but not yet executed. For Not run rows, the Actual result column gives what a code review of the Portal predicts, which must be confirmed by running the test before any issue is filed.
