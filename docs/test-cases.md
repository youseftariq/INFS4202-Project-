# Test design

A spreadsheet `docs/test-cases.xlsx` may replace this file. At least 10 test cases for each of the three primary modules.

**Conventions:**
- **IDs** are `TC-<MODULE>-<NNN>`.
- **Levels:** API means a black-box Engine call; Integration means Portal service + H2 database, with the Engine stubbed; System means the running Portal in a browser.
- **Allowance requests** use the default Settings values unless a row says otherwise: transport supplement 300, monthly cap 5,000, penalty 5% per started week, penalty cap 20%.
- **Statement lines** follow the OpenAPI definition of `/allowance`, in this order: base, transport, cap adjustment, penalty, total.

### Users & Access / Security (USR, SEC): primary module, owner Yousef

**Conventions for this section:**
- **Levels:** *System* = running Portal in a browser after `./start.sh --reset`; *Unit* = Portal class tested alone with JUnit 5 (the rows give the test class); *Static* = code inspection without running the Portal.
- **Technique:** black-box cases are designed from the requirement only; white-box cases come from reading the code. Cases marked *non-functional: security* test SEC-nn requirements; the others test the functional USR-nn requirements.
- **Status:** *Fail* = the defect was reproduced and an issue is open; the automated tests tagged `defect` fail on purpose until the defect is fixed (run them with `-Dgroups=defect`). *Not run* = designed but not yet executed.
